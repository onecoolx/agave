# WatchWeb MCU 优化指南

> 目标：在 Cortex-M55 (200MHz) + 16MB PSRAM 上运行浏览器  
> 用途：作为大模型输出的 UI 渲染层，支持 HTML/CSS/JS/SVG

## 目标能力

| 能力 | 要求 | 说明 |
|------|------|------|
| 表单 | ✅ | input/select/button，用于 LLM 交互 |
| 按钮 | ✅ | 点击触发 JS 回调 |
| 列表 | ✅ | ul/ol/div 列表渲染 |
| 图片 | ✅ | 限制解码尺寸 |
| SVG 图标 | ✅ | 内联 SVG 渲染 |
| CSS 样式 | ✅ | 布局 + 颜色 + 字体 |
| JavaScript | ✅ | DOM 操作 + 事件处理 |
| 文本排版 | ✅ | 多语言 + 自动换行 |

## 硬件约束

```
CPU:    Cortex-M55 @ 200MHz
SRAM:   4 MB (快速，用于代码执行和关键路径)
PSRAM:  16 MB (慢速，用于大块数据)
Flash:  8-16 MB (存储代码和资源)
显示:   480x480 圆形 SPI/MIPI
```

## 内存预算 (16MB PSRAM)

| 组件 | 预算 | 优化措施 |
|------|------|----------|
| Tile buffer | 1.5 MB | 缩小为 600×630×RGB565 (1.5x viewport) |
| Canvas buffer | 0.25 MB | 400×334×RGB565 |
| LVGL | 0.3 MB | 精简控件，禁用动画 |
| DOM + 渲染树 | 4 MB | 限制节点数上限 (~500) |
| CSS 引擎 | 1.5 MB | 限制规则数 |
| QuickJS 堆 | 4 MB | `JS_SetMemoryLimit(rt, 4*1024*1024)` |
| 图片解码 | 2 MB | 限制单张 256×256，渐进解码 |
| 网络缓冲 | 1 MB | 禁用磁盘缓存 |
| 字体 | 0.5 MB | 单字体，按需加载 glyph |
| 系统/栈/其他 | 0.9 MB | |
| **总计** | **~16 MB** | |

## 优化清单

### P0 — 必须完成（才能在 16MB 上运行）

- [ ] **Tile buffer 缩小** — 从 2x3 改为 1.5x viewport，用 RGB565 代替 ARGB8888
- [ ] **QuickJS 内存限制** — 调用 `JS_SetMemoryLimit` 设置 4MB 上限
- [ ] **图片解码限制** — 超过 256×256 的图片缩放后再解码
- [ ] **禁用 HTTP 缓存** — 调用 `macross_set_disk_cache_size(0)`
- [ ] **DOM 节点上限** — 超过 500 节点时停止解析（防止 OOM）

### P1 — 性能优化

- [ ] **PSRAM 分配器** — 大块内存（buffer/图片/JS堆）分配到 PSRAM，小对象留 SRAM
- [ ] **增量渲染** — 页面加载时分块渲染，避免一次性布局整个 DOM
- [ ] **字体缓存** — glyph bitmap 缓存在 SRAM，LRU 淘汰
- [ ] **脏矩形优化** — 只重绘变化区域，减少 blit 面积

### P2 — 体验优化

- [ ] **渐进式加载** — 先渲染文本，后加载图片
- [ ] **JS 延迟执行** — 首屏渲染完成后再执行非关键 JS
- [ ] **预连接** — DNS 预解析 + TCP 预连接
- [ ] **压缩传输** — 确保 gzip/deflate 启用

## LLM UI 场景适配建议

作为大模型输出的 UI 层，页面由服务端生成，可以做以下约定：

1. **限制 DOM 复杂度** — 服务端生成的 HTML 控制在 200 节点以内
2. **内联 CSS** — 避免外部样式表请求
3. **SVG 图标内联** — 避免额外图片请求
4. **使用系统字体** — 不加载 web font
5. **避免重度 JS** — 交互逻辑尽量简单（事件绑定 + fetch）
6. **分页输出** — 长内容分页而非无限滚动

遵循这些约定，内存可控制在 **10MB 以内**，加载时间 **1-2 秒**，完全可在 M55+16MB PSRAM 上流畅运行。
