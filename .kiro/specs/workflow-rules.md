# 项目工作流规范

## 审查规则

每次完成大量修改后，必须进行一次完整的逻辑审视：

1. **初始化/释放配对检查** — 确认每个 init 都有对应的 shutdown，顺序正确，支持重入
2. **引用计数/内存** — 确认 DupValue/FreeValue 配对，缓存命中返回时 DupValue
3. **幂等性** — init/shutdown 可被多次调用不出错
4. **生命周期顺序** — 依赖方先释放，被依赖方后释放（如：JS context 先于 runtime）
5. **遗留注释** — 检查 "intentionally not doing X" 类注释是否仍然成立

## 反复审视原则

对于大型重构，必须从正反两个方向多轮审视：

- **正向**：验证正常流程中每一步的状态转换是否正确
- **反向**：验证异常/边界场景（shutdown 期间回调、NULL 指针、迭代器失效、重入）
- **每轮修复后再审视一轮** — 修复本身可能引入新问题或暴露之前被掩盖的问题
- **直到一轮审视中没有发现新问题为止**

这个方法有效提高代码质量，避免在生产环境中发现难以复现的 crash。
